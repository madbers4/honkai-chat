# Выборочный экспорт Джотаро через CosyVoice3

CLI: `scripts/voice-production/generate-cosyvoice-p1.py`. Он создаёт только внешние файлы для проверки: исходный PCM WAV референса, raw/trimmed WAV каждой реплики, mono 24 kHz MP3 64 kbit/s и `report.json`. Каталоги игры, production MP3 и сценарий не изменяются; команды активации или finalization нет.

Пользователь выбрал пилот **А — по исходному референсу**. Это разрешает рецепт `zero-original`, но не означает слухового одобрения каждой новой реплики. Во всех строках отчёта `userListeningApproved=false`; ASR обозначен `not-run` до отдельной проверки.

| `--recipe` | Пилот | Метод | Референс |
| --- | --- | --- | --- |
| `zero-original` | А, выбран пользователем | `inference_zero_shot`, точная транскрипция «Ублюдок! Дио!» с префиксом CosyVoice3 | Полный `public/assets/voices/jotaro-dio.mp3` |
| `anger-original` | Б | `inference_instruct2`, официальный angry instruction | Тот же оригинал |
| `anger-approved-b` | Г | `inference_instruct2`, тот же angry instruction | Полный ранее одобренный `spoken-v2/faceoff-challenge-p1.mp3` |

Буква Г обозначает новый Cosy-пилот; «approved-b» в имени рецепта обозначает старый Qwen Original B, используемый только как источник тембра. Никакой старый MP3 не копируется как новая реплика.

## Запуск одной реплики

Из checkout проекта в PowerShell:

```powershell
& 'C:/Temp/hsr-cosyvoice3/venv/Scripts/python.exe' -X utf8 scripts/voice-production/generate-cosyvoice-p1.py --recipe zero-original --only faceoff-mode-p1 --model 'C:/Temp/hsr-cosyvoice3/model' --source-repo 'C:/Temp/hsr-cosyvoice3/repo' --output 'C:/Temp/hsr-cosyvoice3/p1-one-review' --validate-only
```

`--validate-only` проверяет выбранные ID, референс, Git revisions и полное содержимое 12 модельных файлов. Он не импортирует Torch/CosyVoice, не создаёт выходной каталог и не использует GPU. После проверки тот же вызов без `--validate-only` выполняет синтез.

Для нескольких реплик `--only faceoff-mode-p1,faceoff-challenge-p1`. Для явно разрешённого полного набора заменить `--only ...` на `--actor p1`; текущий сценарий содержит 28 таких реплик. Эти варианты взаимоисключающие. Имена p2, неизвестные/повторные ID, изменение произносимых слов и выход в Git checkout отклоняются. Выходной каталог должен быть новым или пустым: предыдущие дубли не перезаписываются. Для retry нужен другой внешний каталог.

`--reference` разрешает перемещённую копию источника, но SHA256 должен совпадать с рецептом. `--script` выбирает локальный JSON. `--seed` по умолчанию 62101, одинаково устанавливается перед каждой строкой; seed записывается в отчёт. `--ffmpeg` может указать локальный бинарник, иначе используется бинарник пакета imageio-ffmpeg. Модель и исходники всегда задаются существующими локальными путями.

## Точные параметры и происхождение

- Модель `FunAudioLLM/Fun-CosyVoice3-0.5B-2512`, revision `29e01c4e8d000f4bcd70751be16fa94bf3d85a18`.
- Код CosyVoice `074ca6dc9e80a2f424f1f74b48bdd7d3fea531cc`, Matcha `dd9105b34bf2be2230f4aa1e4769fb586a3c824e`. Требуются чистые tracked-файлы обоих checkout.
- FP16, `load_trt=false`, `load_vllm=false`, `stream=false`, `speed=1.0`, `text_frontend=false`. Темп и высота не меняются. HF/Transformers работают с offline-переменными.
- Референс: полное декодирование, стерео усредняется, PCM16 roundtrip при исходной частоте. Обрезки референса нет.
- Для `faceoff-mode-p1` ввод строго как в Cosy-пилотах: «Дио! Сегодня гнётся не моя броня!». Остальные строки используют `synthesisText`. Слова сверяются с каноническим `text`; сам JSON не меняется.
- Обработка соответствует пилоту: RMS trim с запасом 80 мс, two-pass loudnorm −18 LUFS / −1,5 dBTP / LRA11, fades 6/12 мс, MP3 mono24k64k. Raw FLOAT WAV сохраняется до обработки.

Отчёт содержит recipe/instruction, seed, модельные pins, SHA256 источника и PCM-референса, сценария, генератора, всех raw WAV/WAV/MP3, версии пакетов/FFmpeg, длительности, пиковые уровни, клиппинг, тишину, LUFS и peak CUDA allocation. Неудача оставляет `failed-partial-export` с ошибкой и уже сделанными файлами для диагностики. Это не готовый активный пакет: дальнейшие ASR и слуховая приёмка обязательны для оценки качества, а активация выполняется отдельно.

## Проверки этой реализации

`py_compile` и восемь проверок стандартной библиотеки прошли без GPU: выбор p1, неизменность слов/пилотного ввода, неизвестные/повторные/p2 ID, обязательные аргументы, отказ записи в checkout и непустой каталог, чувствительность хеша к подмене данных, разделение рецептов, отсутствие ML-импортов в валидации. Полный `--validate-only --actor p1` прошёл на локальной закреплённой модели и выбрал ровно 28 ID без записей на диск.

Конкретное окружение и ограничения Python 3.12 описаны в [заметках о методе](VOICE-METHOD-PILOT-NOTES.md). Код не импортирует временные или незакоммиченные генераторы других веток.
