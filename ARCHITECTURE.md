# Устройство игры

React + TypeScript + Vite. Единственный workspace — `client`. В сборке только статические HTML, JavaScript, CSS, шрифты и изображения. Старый общий серверный чат удалён.

`dialogue.ts` хранит направленное дерево реплик; у каждого варианта ответа есть следующий узел и, при необходимости, тон общения. Узел `game` передаёт управление сапёру. Дерево проверяется тестом на достижимость, циклы и длину маршрутов.

`game.ts` содержит чистую функцию `transition(state, action, now)`. Состояния: welcome → dialogue → playing → retry / encore / won / lost. `remaining` хранит остаток активного времени, `runningSince` — начало текущего непрерывного отрезка игры. Во время сюжетной переписки и ожидания повтора отсчёт остановлен. Очередь `pending`, `typingAt` и `messageAt` задают ритм: 350 мс между репликами, длительность печати зависит от длины сообщения. За тик доставляется максимум одна реплика, поэтому после возвращения из фона текст не сваливается одним блоком. После последней реплики поле становится активным.

Первый таймаут добавляет 60 секунд и шестую попытку; пока Искра объявляет подарок, отсчёт стоит. Второй таймаут завершает игру. Быстрая победа (менее 60 секунд активной игры без ошибок) один раз переводит в `encore`: уровень повышается, разговор продолжается без таймера, затем открывается новое поле с прежним бюджетом времени и попыток. Это условие не срабатывает после бонуса.

`commentary.ts` наблюдает переходы состояния: открытые клетки, флажки, серии ходов, паузы игрока, время и оставшиеся попытки. Срочные события приоритетнее обычных комментариев. Для обычных реакций действует интервал 6,5 с, для фоновых — 11 с; недавние реплики исключаются из выбора. После исчерпания банка возвращается самая давно звучавшая реплика. Выбор воспроизводим по seed и номеру реакции. Состояние наблюдателя сохраняется вместе с игрой. Содержимое закрытых клеток не используется для подсказок; комментарии не блокируют поле.

`minesweeper.ts` создаёт поле при первом открытии, исключая выбранную клетку и соседей. Размер и число мин задаёт `difficulty.ts`. Поле воспроизводимо по seed партии, номеру попытки и наличию реванша. Нулевые клетки раскрываются обходом соседей. Флажки не открываются автоматически; победа требует открытия всех безопасных клеток.

`storage.ts` валидирует сохранённый JSON перед загрузкой. `SparxieGame.tsx` сохраняет изменения в sessionStorage; каждая вкладка владеет своим состоянием. При недоступном хранилище игра остаётся в памяти и предупреждает гостя, что перезагрузка не сохранит прогресс.

`LiveCommentary.tsx` оформляет реакции как окно стрима и монтируется только на активном поле. Его высота фиксирована, чтобы смена реплики не двигала клетки. `ResizeObserver` измеряет свободную высоту чата и квадрат поля: изменение размеров окна и панелей браузера перестраивает поле без сброса игры. На маленьких экранах во время игры остаются компактный таймер, переключатель режима и справка по кнопке.

QR строится в браузере библиотекой qrcode. Никаких внешних QR-сервисов и отправки адресов нет. Страница стендовика открывается через `?staff=1`, а значит работает и на статическом хостинге без настройки маршрутов.

Исходный код и состояние находятся у гостя. Часы и сохранение можно намеренно изменить средствами браузера; для фестивального ролевого задания серверная проверка результатов не предусмотрена.
