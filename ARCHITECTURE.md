# Устройство игры

React + TypeScript + Vite. Единственный workspace — `client`. В сборке только статические HTML, JavaScript, CSS, шрифты и изображения. Старый общий серверный чат удалён.

`dialogue.ts` хранит направленное дерево реплик; у каждого варианта ответа есть следующий узел и, при необходимости, тон общения. Узел `game` передаёт управление сапёру. Дерево проверяется тестом на достижимость, циклы и длину маршрутов.

`game.ts` содержит чистую функцию `transition(state, action, now)`. Состояния: welcome → dialogue → playing → retry / won / lost. До обработки любого действия проверяется абсолютный deadline. Таймер нельзя обновить ошибкой, перезагрузкой или возвращением из фоновой вкладки. После терминального состояния игровые действия игнорируются.

`minesweeper.ts` создаёт поле при первом открытии, исключая выбранную клетку и соседей. Поле воспроизводимо по seed партии и номеру попытки. Нулевые клетки раскрываются обходом соседей. Флажки не открываются автоматически; победа требует открытия всех безопасных клеток.

`storage.ts` валидирует сохранённый JSON перед загрузкой. `SparxieGame.tsx` сохраняет изменения в sessionStorage; каждая вкладка владеет своим состоянием. При недоступном хранилище игра остаётся в памяти и предупреждает гостя, что перезагрузка не сохранит прогресс.

QR строится в браузере библиотекой qrcode. Никаких внешних QR-сервисов и отправки адресов нет. Страница стендовика открывается через `?staff=1`, а значит работает и на статическом хостинге без настройки маршрутов.

Исходный код и состояние находятся у гостя. Часы и сохранение можно намеренно изменить средствами браузера; для фестивального ролевого задания серверная проверка результатов не предусмотрена.
